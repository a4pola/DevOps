# Разбор протокола ARP и вопросов безопасности

## 1. Разбор ARP-таблицы и риски безопасности

Вывод ARP-таблицы с маршрутизатора `R1` (`show ip arp`):

```text
Protocol  Address          Age (min)  Hardware Addr   Type   Interface
Internet  10.10.10.2              0   c402.4b03.0000  ARPA   FastEthernet0/0
Internet  10.10.10.1              -   c401.20ec.0000  ARPA   FastEthernet0/0
```

### Значение колонок:
* **`Protocol`** — тип сетевого протокола (`Internet` соответствует протоколу IPv4).
* **`Address`** — логический IPv4-адрес узла в локальной сети (`10.10.10.2` — соседнее устройство, `10.10.10.1` — собственный интерфейс).
* **`Age (min)`** — время жизни (возраст) записи в минутах. Числовое значение (`0`) указывает на динамическую запись, полученную по ARP, которая удалится по истечении тайм-аута. Символ `-` обозначает собственный интерфейс устройства, запись о котором не устаревает.
* **`Hardware Addr`** — аппаратный (MAC) адрес сетевого интерфейса, сопоставленный с IP-адресом.
* **`Type`** — тип инкапсуляции кадра на канальном уровне (`ARPA` — стандартный Ethernet II).
* **`Interface`** — локальный сетевой интерфейс маршрутизатора, через который доступен узел.

### Разница между `dynamic` и `static` записями и риски безопасности:
* **Динамические записи (`dynamic`)** формируются автоматически при обмене ARP-сообщениями и хранятся ограниченное время. Это избавляет администратора от ручной настройки, но создаёт критическую уязвимость: протокол ARP не имеет встроенных механизмов проверки подлинности (аутентификации) отправителя. Любой узел в локальной сети может отправить поддельный ARP-ответ, и получатель автоматически перезапишет свою динамическую таблицу.
* **Статические записи (`static`)** задаются администратором вручную жёсткой привязкой «IP — MAC». Они не перезаписываются динамическими ARP-ответами и защищают от подмены, но требуют ручного сопровождения при масштабировании сети.

## 2. Логика атаки ARP-spoofing (Man-in-the-Middle)

В структуре ответного пакета **ARP Reply** (`10.10.10.2 is at c4:02:4b:03:00:00`) передаются четыре ключевых адресных поля: `Sender MAC address`, `Sender IP address`, `Target MAC address` и `Target IP address`.

**Логика подмены для перехвата трафика («человек посередине»):**
1. Злоумышленник в той же локальной сети формирует поддельный пакет **ARP Reply** для жертвы `R1` (`10.10.10.1`).
2. В поле **`Sender IP address`** он указывает IP-адрес легитимного соседа (`10.10.10.2`), а в поле **`Sender MAC address`** подставляет **свой собственный MAC-адрес**.
3. Жертва `R1`, доверяя полученному ответу, обновляет свою ARP-таблицу, связывая IP `10.10.10.2` с MAC-адресом атакующего.
4. Аналогичный поддельный пакет отправляется второму узлу `R2` (`10.10.10.2`) с подменой пары `Sender IP = 10.10.10.1` на MAC-адрес злоумышленника.
5. В результате весь канальный трафик (L2) между `R1` и `R2` начинает проходить через устройство атакующего.

## 3. Итоговая формулировка ответа на вопрос

Первый ARP-запрос (ARP Request) на канальном уровне (L2, заголовок Ethernet II) отправляется на **широковещательный (Broadcast) MAC-адрес `ff:ff:ff:ff:ff:ff`**. Это необходимо для доставки запроса всем узлам в пределах локального широковещательного домена, так как физический адрес целевого устройства отправителю ещё не известен (внутри самого заголовка ARP в поле `Target MAC` при этом указываются нули `00:00:00:00:00:00`).
